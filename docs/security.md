## 1. Критично — закривати до наступного відкриття тунелю

### [x] 1.1 Список пасажирів рейсу відкритий без авторизації

```
GET /api/rides/3/bookings   →  200, усі ПІБ / телефони / міста
```

- Де: `backend/routers/rides.py`, функція `ride_bookings` — немає `Depends`.
- Лендінгу цей ендпоінт **не потрібен** (він тягне лише `/api/rides`,
  `/api/routes/{id}`, `POST /api/bookings`, `/api/parcels/track/*`,
  `/api/public/config`).
- Фікс: додати `_=Depends(require_staff_or_bot)`. Адмінка й бот ходять з
  токеном/ключем, для них нічого не зміниться.

### [x] 1.2 `GET /api/rides` віддає повну картку водія

```json
"driver": {"phone": "+380…", "telegram_id": 555123456, "invite_code": null}
```

- Де: `backend/schemas.py`, `RideOut.driver: Optional[UserOut]`. `UserOut`
  містить `phone`, `telegram_id`, `invite_code`.
- Чому небезпечно: `invite_code` зараз `null`, бо активних запрошень немає.
  Але щойно в адмінці натиснути «запросити» для водія, що стоїть на рейсі,
  код з'явиться в цій **публічній** відповіді. Далі API не потрібен —
  достатньо відкрити `t.me/<bot>?start=drv_<код>`, і бот прив'яже акаунт
  водія до чужого Telegram. Ця людина побачить маніфест рейсу з пасажирами.
- Фікс: окрема схема `DriverPublic(id, full_name)` для `RideOut.driver`;
  `phone`, `telegram_id`, `invite_code` лишити тільки в `UserOut`, який
  повертають адмінські ендпоінти `/api/users`.

### [x] 1.3 Бронь і посилку може створити будь-хто, без обмежень

- `POST /api/bookings`, `POST /api/parcels` — без авторизації (так і задумано,
  це форма на сайті), але **без rate limit**. Кожна бронь одразу пінгує
  батька «запиши в книжку».
- Фікс (мінімальний): ліміт на IP — напр. 5 броней за 10 хв, далі 429;
  однакові телефон+рейс за короткий час — не дублювати, а оновити. Бот
  спілкується з API через `X-Bot-Key`, тож його під ліміт не підводити.
- Фікс (кращий): нові броні з сайту потрапляють у чергу зі статусом
  «на підтвердження», батькові йде **одне** зведене повідомлення раз на
  N хвилин, а не по одному на кожну.
- Зроблено мінімальний: `backend/ratelimit.py` — 5 заявок / 10 хв на IP для
  `POST /api/bookings` і `POST /api/parcels` (разом), бот і адмінка з
  токеном не лімітуються (`auth.trusted_caller`). Повторна заявка з тим
  самим телефоном на той самий рейс протягом 10 хв **оновлює** попередню
  без нового пінгу. Анонімний виклик не може видати себе за водія/адміна:
  `source` примусово `web`, `telegram_id` скидається. Зведене повідомлення
  (кращий фікс) — не робилось.

## 2. Важливо — до виходу на реальний домен

### [x] 2.1 Пароль адмінки можна підбирати без обмежень

- `POST /auth/token` — п'ять невірних спроб поспіль дали п'ять 401 без
  затримки. Логін `admin` — стандартний, тобто підбирати треба лише пароль.
- Фікс: `slowapi` або власний лічильник у пам'яті — 5 спроб/хв на IP,
  далі 429 з наростаючою затримкою; змінити логін з `admin` на щось своє
  (`ADMIN_USERNAME` в `.env` + `seed.py`).
- Зроблено: `ratelimit.LoginGuard` — 5 невдалих спроб, далі 1 хв, 2, 4…
  до 15 хв; вдалий вхід скидає. Логін змінити — руками (див. «Після деплою»).

### [x] 2.2 `/docs`, `/redoc`, `/openapi.json` публічні

- Готова карта всього API. У `backend/main.py`:
  `FastAPI(..., docs_url=None, redoc_url=None, openapi_url=None)` або
  вмикати лише коли `DEBUG=1`.

### [x] 2.3 JWT живе 30 днів і не відкликається

- `backend/auth.py`, `ACCESS_TOKEN_EXPIRE_HOURS = 24 * 30` — свідомо, щоб не
  викидало посеред дня виїзду. Ціна: вкрадений токен (залишена сесія на
  чужому комп'ютері, XSS) дійсний місяць; «вийти» лише стирає localStorage.
- Фікс: колонка `token_version` в `users`, у JWT класти `ver`; при зміні
  пароля або кнопці «вийти всюди» — `ver += 1`, старі токени вмирають.
  Заодно з'явиться зміна пароля, якої зараз немає в UI.
- Зроблено: `POST /auth/change-password`, `POST /auth/logout-all`
  (`backend/routers/account.py`), в адмінці сторінка «⚙️ Акаунт». Токени
  без `ver` не приймаються — **після деплою всі адмінські сесії злетять
  один раз**, це очікувано.

### [x] 2.4 Тунель ngrok виносить назовні весь стек разом з `/admin`

- `frontend/nginx.conf`: `/admin/` — статика без гейта, єдиний захист —
  форма логіну (див. 2.1).
- Фікс на час тунелю: `auth_basic` в nginx перед `location /admin/`
  (логін/пароль в `.htpasswd`, поза git). На постійному домені — той самий
  basic auth або IP-allowlist для `/admin`.
- Пам'ятати: **тунель піднімати на час роботи й закривати**. Не лишати на
  ніч.
- Зроблено: `ADMIN_BASIC_USER` / `ADMIN_BASIC_PASSWORD` в `.env` → nginx
  вмикає basic auth на `/admin/` при старті (`frontend/admin-auth.sh`,
  `.htpasswd` генерується в контейнері, в git не потрапляє). Обидві
  порожні — без замка, як локально.

### [x] 2.5 Немає security-заголовків

- В nginx додати:
  ```
  add_header X-Frame-Options DENY;              # /admin не вкласти в iframe
  add_header X-Content-Type-Options nosniff;
  add_header Referrer-Policy strict-origin-when-cross-origin;
  add_header Strict-Transport-Security "max-age=31536000" always;  # лише під HTTPS
  ```
  Для лендінгу `X-Frame-Options` не потрібен — ставити тільки на `/admin/`.
- Зроблено. HSTS іде лише коли `X-Forwarded-Proto: https` (ngrok/проксі),
  на голому http заголовок порожній і nginx його не шле.

## 3. Варте уваги — коли дійдуть руки

### [x] 3.1 Кнопку водія можна «натиснути» текстом

- `bot/bot.py`, хендлер `cmd_book` ловить `F.text == BTN_DRV_BOOK`. Пасажир,
  що надішле рядок «➕ Записати пасажира», створить бронь із
  `source: "driver"` і без свого `telegram_id`. Не витік, але бреше про
  походження запису.
- Фікс: у `cmd_book` ставити `as_driver` лише якщо `staff_user()` підтвердив
  роль `driver`.

### [x] 3.2 Водій може видалити машину й історію ТО

- `backend/routers/vehicles.py` — усі ендпоінти на `get_current_user`.
  Читання — ок для водія, а `POST/PATCH/DELETE` перевести на `require_admin`.

### [x] 3.3 `verify_bot_key` порівнює через `==`

- `backend/auth.py`. Поруч `require_staff_or_bot` вже робить
  `hmac.compare_digest` — зробити так само.

### [x] 3.4 Розмір фото перевіряється після повного читання

- `backend/storage.py`, `save_parcel_photo`: `upload.file.read()` цілком, і
  лише потім `len()`. nginx ріже на 12 МБ (`client_max_body_size`), тож
  через nginx не страшно; при прямому доступі до backend — можна залити
  гігабайти на диск. Читати чанками з лічильником, або перевіряти
  `Content-Length` до читання. Magic bytes не перевіряються — XSS звідси не
  виходить (StaticFiles ставить `image/*` за розширенням), але для
  гігієни варто.

### [x] 3.5 Бекапів немає

- `data/data.db` і `media/` — bind mounts на тому ж диску. Втрата диска =
  втрата всього, чого немає в книжці (посилки, фото, історія).
- Мінімум: cron-контейнер, що раз на добу робить
  `sqlite3 data.db ".backup data-YYYY-MM-DD.db"` + `tar` для `media/` і
  кладе в іншу локацію (інший диск, S3/Backblaze, хоч Google Drive).
  Зберігати 30 днів.
- Зроблено: сервіс `backup` у compose (`backup.sh`): щодня о `BACKUP_HOUR`
  (04:00) + одразу при старті, зберігає `BACKUP_KEEP_DAYS` (30) днів у
  `BACKUP_DIR` (типово `./backups`, в `.gitignore`). **Той самий диск — не
  бекап**: `BACKUP_DIR` треба вказати на інший диск або теку, яку синхронізує
  хмара.

### [x] 3.6 Персональні дані: строк зберігання

- Телефони й домашні адреси пасажирів лежать вічно. Чехія — ЄС, GDPR.
- Рішення: раз на місяць чистити броні старші за N місяців (або
  анонімізувати: лишити місто/місця для статистики, стерти ПІБ/телефон/
  адресу). N узгодити: для бухгалтерії/претензій зазвичай 12 міс.
- Додати на лендінг коротку політику конфіденційності (хто ми, що
  зберігаємо, скільки, як видалити).
- Зроблено: `backend/retention.py`, щомісяця 1-го о 04:00 — броні й посилки
  старші за `RETENTION_MONTHS` (12) анонімізуються (ПІБ/телефон/адреси/
  коментар/telegram_id → стерті, місто/дата/місця лишаються), старі
  `telegram_contacts` видаляються. На лендінгу секція `#privacy` + згадка
  під формою; текст обіцяє 12 місяців — якщо міняти `RETENTION_MONTHS`,
  поправити й текст.

## Що вже зроблено правильно (не чіпати)

- Паролі — bcrypt.
- Telegram `initData` для Mini App перевіряється по-справжньому: HMAC від
  токена бота, `compare_digest`, `auth_date` не старший 24 год.
- `.env` ніколи не потрапляв у git (перевірено по історії). Секрети змінені
  з дефолтних (`SECRET_KEY`, `BOT_API_KEY`, `ADMIN_PASSWORD`).
- Імена завантажених файлів — uuid, обходу шляху немає; розширення —
  allowlist.
- Трек-номер посилки віддає лише статус, без персональних даних
  (`ParcelTrackOut`).
- `/api/book/scan` (OCR через Opus) — під `require_admin`, рахунок за API
  ніхто ззовні не накрутить.
- CORS обмежений localhost-origin'ами для dev; у проді запити йдуть з того
  самого origin через nginx.

## Робота з іншого комп'ютера

Що **не в git** і що треба перенести окремо, безпечним каналом (не поштою,
не в Telegram «Обраному» без пароля — краще менеджер паролів або файл на
зашифрованій флешці):

| Файл / тека         | Що там                                                  |
|---------------------|----------------------------------------------------------|
| `.env`              | токен бота, `ANTHROPIC_API_KEY`, `SECRET_KEY`, `BOT_API_KEY`, пароль адміна, дані Нової Пошти |
| `data/data.db`      | база: броні, посилки, користувачі                        |
| `media/`            | фото посилок і бусів                                     |
| `images/`           | скани сторінок книжки (телефони пасажирів)               |
| `data/splits.txt`   | датасет розділень (міста реальних пасажирів)             |

Після клонування: скопіювати `.env`, зробити `docker compose up -d --build`,
зайти в адмінку. Якщо база потрібна та сама — переносити `data/data.db`
**при зупиненому** backend, інакше SQLite може лишитись у неконсистентному
стані.

Якщо `.env` колись потрапить не туди — вважати всі ключі скомпрометованими:
перевипустити токен бота (`/revoke` у BotFather), ключ Anthropic (консоль),
згенерувати нові `SECRET_KEY` і `BOT_API_KEY` (це одразу вб'є всі сесії
адмінки — так і треба).

## Після деплою (руками)

1. `docker compose up -d --build` — бекенд, бот і nginx усі змінились;
   `backup` сервіс підніметься сам.
2. У `.env` додати `ADMIN_BASIC_USER` / `ADMIN_BASIC_PASSWORD` (інші, ніж
   логін адмінки) і `BACKUP_DIR` на інший диск. Зразок — `.env.example`.
3. Зайти в адмінку заново (старі сесії вмерли), в «⚙️ Акаунт» поставити
   новий пароль. Логін `admin` → свій: `ADMIN_USERNAME=…` в `.env` і
   `python seed.py` створить нового адміна; старого `admin` видалити через
   `/api/users` або в sqlite.
4. Перевірити з зовнішньої адреси: `/api/rides/1/bookings` → 401,
   `/docs` → 404, `/admin/` питає basic auth.
