# Датасет розподілу пасажирів по бусах

## Навіщо

Адмінка вміє запропонувати, як розділити пасажирів дня між бусами
(`/admin/split`). Зараз вона це робить за правилом, яке я відновив із двох
ваших прикладів (15.09 і 17.09): **один бус — один коридор**, і різати треба
по межі регіону, а не порівну.

Два приклади — замало, щоб довіряти. Потрібні ваші справжні розподіли за
10–20 днів. Із них:

1. витягну всі міста, які реально трапляються, і розкладу їх по зонах за тим,
   з ким вони їздять разом, а не за моїми здогадками;
2. прожену кожен день через алгоритм і побачу, де він ділить не так, як ви;
3. після виправлень назву чесний відсоток збігу.

## Формат

Файл `data/splits.txt` (він у `.gitignore` — реальні маршрути пасажирів
у GitHub не потрапляють). Один день — дата, потім машини:

```
17.09
1: Hlavenec - Костопіль, Літомишль - Костопіль, Hostinne - Рівне, Врхлабі - Здолбунів, Jicin - Луцьк
2: Прага - Радивилів, Тепліце - Бродівське, Хомутов - Остріг, Трешт - Кременець, Мост - Львів

15.09
1: Кременець - Bilina, Рівне - Кадань, Остріг - Хомутов, Красне - Мост, Петричі - Мост
2: Малі Сади - Skrdlovice, Рівне - Брно x3
```

Правила:

- **Між містами — дефіс** (`-`, `–` або `>`), бо є двослівні міста: «Малі Сади»,
  «Карлові Вари».
- Записи в одній машині — через кому.
- Якщо в записі кілька людей — `x3` наприкінці. Без цього — одна людина.
- Напрямок не пишіть: він визначається з дня тижня (вт/пт — з України,
  чт/нд — з Чехії). Якщо день був позаплановий, допишіть після дати:
  `21.08 UA->CZ`.
- Телефони, адреси, імена не потрібні.
- Написання міст — як у зошиті. Нормалізувати не треба, це моя робота.
- Рік не потрібен, якщо це поточний рік. Для минулого року: `21.08.2025`.

Найкорисніші дні — **різні**: з трьома й чотирма бусами, з рідкісними
містечками, обидва напрямки, дні з людьми з Луцька і Львова.

## Як перевірити

```bash
docker compose exec -T backend python eval_split.py /app/data/splits.txt
```

(або `python backend/eval_split.py data/splits.txt`, якщо `anthropic` не
блокується локально). Скрипт друкує по кожному дню, чи розділив як ви, а де
ні — показує обидва варіанти поруч. Наприкінці — відсоток збігу і список міст,
яких ще нема в зонах.

Номери бусів не важливі: порівнюється, чи двоє пасажирів їдуть разом чи
окремо, — так само, як ви їх і ділите.

## Що вже відомо про правило

Зони і їх порядок — у `backend/split.py`, `CZ_ZONES` та `UA_ZONES`.

Порядок чеських зон — це порядок, у якому їх проїжджає бус:

```
захід → північ → прага → височина → морава   ← коридор через Прагу і D1
                                       схід   ← окремий коридор через Градець–Пардубіце
```

Алгоритм сортує пасажирів за чеською зоною (для UA→CZ — куди, для CZ→UA —
звідки), всередині — за українською, і ріже там, де зона змінюється. Порівну
ділить лише зону, що не влазить у 8.

## Відкриті питання

Це те, чого я з двох прикладів не бачу. Відповіді або з датасету, або словами:

- **Ліберець** — їде північним коридором (через Їчін) чи через Прагу?
- **Пілзень, Карлові Вари** — через Прагу, як Мост і Хомутов? Зараз вони
  першими в празькому коридорі.
- **Чи бере участь українська сторона?** Чи буває, що бус визначає не Чехія,
  а те, що всі з Луцька, наприклад?
- **Закреслений рядок, під яким уже є записи** (23.08: ⑨ закреслено, далі ⑪).
  Ліпа–Степань того дня — 2 людини чи 5? Від цього залежить, як рахувати
  такі випадки при скануванні.

## Що далі, коли датасет буде

Кожен збережений розподіл в адмінці — теж приклад. Наступний крок після
перевірки на датасеті: зберігати поруч із вашим розподілом і те, що
запропонував алгоритм, щоб відсоток збігу рахувався сам, з кожним днем.
