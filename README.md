# craft_trans_bot

Система для пасажирських перевезень і посилок Україна ⇄ Чехія:
Telegram-бот для пасажирів, Mini App для водіїв, адмінка для менеджера
і публічний лендінг з онлайн-бронюванням.

## Що де живе

| Адреса | Для кого | Що робить |
|--------|----------|-----------|
| `/` | клієнти | Лендінг: маршрути, розклад, бронювання, перевірка посилки за трек-номером |
| `/driver` | водії | Telegram Mini App: маніфест на сьогодні, дзвінок/навігатор у тап, забрав/доставив, готівка |
| `/admin` | менеджер | Рейси, бронювання, посилки, маршрути, водії, автопарк, рентабельність |
| `/api`, `/auth` | — | REST API (Swagger на `/docs`) |
| Telegram-бот | клієнти | `/book`, `/parcel`, `/track`, `/my_bookings`, нагадування |

## Архітектура

```
┌──────────┐   HTTP   ┌─────────────┐
│ Telegram │◄────────►│   backend   │  FastAPI + SQLAlchemy
│   бот    │  outbox  │  (API, лендінг, Mini App)
└──────────┘          └──────┬──────┘
                             │
                      ┌──────▼──────┐
                      │  frontend   │  React + nginx (адмінка)
                      └─────────────┘
```

Бот ніколи не ходить у базу напряму — тільки через API. API, своєю чергою,
не викликає Telegram: він складає повідомлення в таблицю `notifications`,
а бот її розбирає. Тому перезапуск бота не втрачає жодного сповіщення.

## Запуск

### Docker (рекомендовано)

```bash
cp .env.example .env      # заповніть TELEGRAM_TOKEN, SECRET_KEY, BOT_API_KEY, WEBAPP_URL
docker compose up -d --build
docker compose exec backend python seed.py   # адмін + маршрути + рейси на 2 тижні
```

Відкрити: лендінг `http://localhost:8080/`, адмінка `http://localhost:8080/admin`.

### Локально без Docker

```bash
python -m venv .venv && .venv/Scripts/activate     # Linux/Mac: source .venv/bin/activate
pip install -r backend/requirements.txt -r bot/requirements.txt

cd backend && python seed.py && uvicorn main:app --reload   # :8000
cd bot && python bot.py
cd frontend && npm install && npm run dev                    # :5173
```

## Налаштування

Всі змінні — у `.env` (шаблон у `.env.example`):

| Змінна | Навіщо |
|--------|--------|
| `TELEGRAM_TOKEN` | Токен бота. Ним же перевіряється підпис Mini App |
| `BOT_USERNAME` | Без `@` — лендінг показує посилання на бота |
| `SECRET_KEY` | Підпис JWT для адмінки. **Обов'язково змініть** |
| `BOT_API_KEY` | Спільний ключ між ботом і API. **Обов'язково змініть** |
| `WEBAPP_URL` | Публічний **HTTPS**-домен. Без нього Mini App не відкриється |
| `REMINDER_HOUR` | О котрій годині ставити в чергу нагадування на завтра (за замовч. 10) |
| `NOTIFY_POLL_SECONDS` | Як часто бот забирає сповіщення з черги |

### Щоб водій міг відкрити маніфест

1. Водій дізнається свій Telegram ID у [@userinfobot](https://t.me/userinfobot).
2. Ви створюєте його в адмінці на сторінці **Водії** і вписуєте цей ID.
3. Призначаєте водія на рейс (сторінка **Рейси**).
4. Водій пише боту `/driver` і відкриває маніфест.

Mini App працює **тільки по HTTPS** — це вимога Telegram. Для тесту згодиться
`ngrok http 8080`, для продакшну — домен із сертифікатом.

## Що варто зробити перед бойовим запуском

- **Alembic для міграцій.** Зараз таблиці створюються через `create_all`:
  зміна моделі не оновить наявну базу. Поки даних немає — це не проблема,
  після першого реального рейсу вже буде.
- **PostgreSQL замість SQLite** — коли з'явиться більше одного менеджера.
- **Ліміт на публічну форму бронювання.** `POST /api/bookings` відкритий
  (інакше лендінг не працюватиме), тож спамом можна «забити» місця в рейсі.
  Мінімум — rate limit по IP.
- **Бекап** `data/data.db` і `media/parcels/` — там фото посилок клієнтів.
